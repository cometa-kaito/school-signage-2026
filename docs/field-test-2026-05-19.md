**前提**: 既存サイネージは未稼働（壊しても本番影響なし）

## Step 1: ベースライン確認（5分）

学校WiFi自体が正常に動いているか確認。これが失敗すると以降のテストに意味がない。

| チェック | 期待 | 失敗時 |
|---|---|---|
| スマホで `google.com` 開く | ✅ 表示 | WiFi自体に問題、IT担当者へ連絡 |
| スマホで `school-signage.net`（LP）開く | ✅ 表示 | Vercelもブロック → フィルタ厳しめ |
| スマホで `school-signage-2026.web.app`（旧URL）開く | ❌ ブロック想定 | 通ったらフィルタ仕様変更されたかも |

---

## Step 2: 新ドメインの到達性（5分）★最重要

**ここが今回のテストの核心**。フィルタが新ドメインを通すかどうか。

### 2-1. スマホで開く
- [ ] `https://app.school-signage.net/` をブラウザで開く
- [ ] 期待: 「ガイド画面へ移動しています...」→ キミテラスのロゴが表示される

### 2-2. PC で開く（Chrome F12 を開いた状態で）
- [ ] 同じ URL を PC で開く
- [ ] DevTools の **Network タブ** で `app.school-signage.net` への接続を確認
- [ ] HTTPS で `200 OK` が返ってくるか

### 結果別アクション

| 結果 | 判定 | 次の Step |
|---|---|---|
| ✅ ページが表示される | フィルタ通過 | → Step 3 へ |
| ❌ ブロックページ表示 | カテゴリ拒否 | → 終了、Cloudflare 前段化検討 |
| ❌ DNS解決失敗（このサイトにアクセスできません） | DNSフィルタ | → 終了、要相談 |
| ⚠️ SSL警告 | 証明書問題 | → スクショ取得、要調査 |

## Step 3: Firestore 通信確認（10分）

サイネージ表示の本体。**学校で `*.web.app` が通らない理由が「Googleドメイン全般ブロック」だった場合、ここで失敗する**。

### 3-1. サイネージ実画面を開く

事前に `/manage/editor` で学校 → クラスを選択し、サイネージURLを取得しておく:
```
https://app.school-signage.net/?school=5tdbeclk5fce&grade=XXX&class=YYY
```

PC で開き、F12 → Console と Network タブを開いておく。

### 3-2. 期待される表示
- [ ] 予定 / 連絡事項 / 提出物が描画される
- [ ] 広告画像がローテーションする
- [ ] 5秒以上待っても「読み込み中」のままにならない

### 3-3. ログ確認（Console タブ）
以下のいずれかが出るはず:

| ログ | 意味 | 判定 |
|---|---|---|
| `Firestore connected` 等 | リアルタイム同期動作 | ✅ 最良 |
| `falling back to JSON polling` | フォールバック動作 | ⚠️ 実用OK（リアルタイム性が秒→数秒に劣化） |
| 大量の `failed`, `TimeoutError` | 通信不可 | ❌ 要対策 |

### 3-4. ネットワーク確認（Network タブ）
- [ ] `firestore.googleapis.com` への接続: 200 / 101 が出ているか
- [ ] `storage.googleapis.com` から画像取得: 200 が出ているか
- [ ] 失敗があれば: URL と応答コード（403/404/タイムアウト/ブロック）を記録

---

## Step 4: 管理画面ログイン（10分）

Firebase Auth が動くか確認。**Authorized Domain 追加済み（5/16）**。

### 4-1. エディターログイン
- [ ] `/manage/login` → 「エディター」タブ → 学校パスワード入力
- [ ] ログイン成功すると `/manage/editor` に遷移

### 4-2. データ編集
- [ ] 適当な日付に「テスト連絡事項」を1件追加 → 保存
- [ ] 別タブで開いていた **サイネージ画面（Step 3）に数秒で反映される** か確認
  - → ✅ Firestore 双方向通信OK
  - → ⚠️ 反映が10秒以上 = JSONフォールバック中（実用範囲）
  - → ❌ 反映されない = 書き込みも失敗

### 4-3. 管理者ログイン（Google認証）
- [ ] `/manage/admin` → メールアドレスでログイン または「Google でログイン」
- [ ] 期待: ログイン成功
- [ ] 失敗時、エラーが `auth/unauthorized-domain` の場合: Authorized Domain 設定に問題（要確認）

## 結果別の次アクション

### 全部 ✅
→ 5/26 のキオスク端末展開に進める。順調。

### Step 3 だけ ⚠️（フォールバック動作）
→ 実用上 OK。リアルタイム性は秒→数秒に劣化するが、サイネージは表示される。
→ 「リアルタイム同期前提の運用」を「数秒遅延あり」と認識して進める。

### Step 2 で失敗（ページが開かない）
→ Cloudflare 前段化を即時検討。Day 6-9 (5/20〜5/23) のバッファ期間で対応。
→ キオスク端末への新URL展開は **延期**、5/28 稼働は危険信号。

### Step 4 で `auth/unauthorized-domain`
→ Firebase コンソールの Authentication → 設定 → 承認済みドメインを再確認。
→ `app.school-signage.net` が登録されているか。

### Step 5 で画像が表示されない
→ Storage バケット (`firebasestorage.app`) が独立してブロックされている可能性。
→ Cloudflare R2 または Storage の独自ドメイン化を検討。
